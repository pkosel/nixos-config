# AGENTS.md

## What this is

Philipp's personal NixOS configuration: a single flake that builds one host,
`frieda` (x86_64 desktop, GNOME), together with the environment of its one
user. Home Manager is integrated as a NixOS module, so system and user
environment are built and activated together; there is no standalone
`homeConfigurations` output. `README.md` covers installation and day-to-day
workflows.

## Common commands

```sh
nix fmt                                   # format all Nix files (nixfmt-tree)
nix flake check                           # evaluate all flake outputs
nixos-rebuild build --flake .#frieda      # build the system without activating it

nix eval .#nixosConfigurations.frieda.config.<option>   # inspect an option's value
nix build .#nixosConfigurations.frieda.pkgs.<package>   # build one package from the overlaid set
```

There is no CI and no test suite. A change is correct when `frieda` evaluates
and builds.

## Architecture

`flake.nix` defines the inputs, the formatter and `nixosConfigurations.frieda`,
which is composed of:

1. The nixpkgs settings (`system/nixpkgs.nix`): overlays that add packages from
   other flakes and from `pkgs/` (via `overlays/`) and patch individual
   nixpkgs packages where needed.
2. `hosts/frieda/configuration.nix`: the host itself (boot, locale, users,
   the WebDAV share, base system packages) plus an import list of modules from
   `system/`.
   `hosts/frieda/hardware.nix` is generated by `nixos-generate-config`.
3. The Home Manager NixOS module, with `users/philipp.nix` as the user profile.
   It imports modules from `home/` and lists packages that need no
   configuration of their own.

Flake inputs reach both NixOS and Home Manager modules as the `inputs`
argument. Home Manager modules also receive `theme`, the shared terminal
palette defined in `home/theme.nix`.

### Modules

Each file under `system/` and `home/` configures one concern and has no effect
until it is imported; directories collect their files in a `default.nix`.
Machine-specific settings belong in `hosts/`, not in modules. To see what the
system actually runs, read the import lists rather than searching by option
name. The Neovim configuration is Lua under `home/editors/nvim/`, concatenated
into `initLua` from the file list in its `default.nix`; open cleanup items are
in `home/editors/nvim/TODO.md`.

### Versions and pins

`nixpkgs` and `home-manager` track the same release branch (26.05) and are
bumped together; other flake inputs follow this nixpkgs. The `stateVersion`s
(25.11) record the original install and do not move with releases. Deliberate
pins and workarounds, such as the legacy nvim-treesitter (which emits
deprecation warnings until migrated), carry a comment explaining why. New ones
should too.

### Secrets

There is no secrets management. Everything in the repository ends up
world-readable in `/nix/store`, so credentials are kept outside it.

## Comments

A comment says why, not what: the constraint, the workaround, or the reason a
setting differs from the default. It describes the current state; history
belongs in the commit message. A workaround names the condition under which it
can go. Unused code is deleted, not commented out.

## Working in this repo

Flakes only see git-tracked files, so new files must be `git add`ed before a
build picks them up. Changes are verified by building, not by activating.
Unless asked, do not activate or install the system (`nixos-rebuild
switch`/`boot`, `nixos-install`), update `flake.lock`, use `sudo`, run
`scripts/setup-partitions` (it repartitions a disk), or commit.
